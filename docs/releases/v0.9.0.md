## Publication completion boundary

After the final source commit, use the external `docxology/template` engine
with this repository linked as `projects/working/white_line`. Follow the
path-independent setup in [development](../development.md), then run from the
engine root:

```bash
uv run python scripts/pipeline/stage_03_render.py --project working/white_line
uv run python scripts/pipeline/stage_04_validate.py --project working/white_line
```

Return to this repository and run:

```bash
uv run python scripts/audit_project.py --require-render --write-manifest --report
```

These are mandatory remaining publication gates, not optional substitutes for
native tests. The native PDF check recognizes a signature only; full PDF and
rendered-provenance validation belong to the external engine. Bind generated
publication evidence to the actual final source commit, not an earlier packet.
The ordinary standalone release tag is `v0.9.0` after those gates pass.
