# Compatible publication validation — 2026-10-21

White Line's source and rendered gates remain independent. The native audit
does not replace the external engine's publication validator. For this release,
the complete unchanged validator ran in Linux against the same canonical source
and rendered bytes after native macOS piped Git calls hung.

Use a Git worktree of template at
`4670c48cc490636455f2eac09ba4396baed9ffd7`, with this checkout linked at
`projects/working/white_line`. An archive export suffices for rendering but
does not supply the Git provenance required by current Stage 04. An independent
bare clone plus detached worktree preserves an active canonical engine owner.

On a compatible Linux host, with a supported external interpreter and uv
environment, the validation command is the ordinary engine CLI:

```bash
export WHITE_LINE_ROOT="$(pwd)"
export TEMPLATE_ROOT="${TEMPLATE_ROOT:?set the independent engine checkout}"
export SOURCE_DATE_EPOCH="$(git -C "$WHITE_LINE_ROOT" show -s --format=%ct HEAD)"
cd "$TEMPLATE_ROOT"
uv sync --locked --no-default-groups --no-dev
uv run --no-sync python scripts/pipeline/stage_04_validate.py --project working/white_line
```

The platform-specific launcher and exact bindings are retained in the release
evidence archive. Docker is an optional way to supply that Linux host; it is
not a White Line package dependency. This run used an already cached image
identified by digest in the main packet, with a read-only container root.
The Python base runtime was copied onto the development volume, and both
`sys.prefix` and `sys.base_prefix` were verified there. Writable environments,
caches, temporary files, the independent engine checkout and project outputs
were mounted on that same volume. The engine's Git metadata was also mounted
so provenance checks could run normally.

The positive gate passed content, design, figure, evidence, artifact-manifest
and rendered-provenance checks. The negative control used a disposable clone
of the project with copied output and a deliberately truncated PDF. The same
CLI exited 1 and reported failures for PDF validation and enabled render
outputs. The canonical PDF retained its recorded SHA-256 throughout. The
control's damaged files are not release deliverables.

The earlier native transport and archive-provenance failures remain in the
run history. No check was replaced with a file-backed shortcut and no engine
code was patched. Re-run validation and regenerate the provenance receipt for
the clean release commit after any input change; do not relabel an older
receipt as evidence for a newer tree.
